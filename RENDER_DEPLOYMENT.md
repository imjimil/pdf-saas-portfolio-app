# Deploying the backend to Render

The API ships as a **Docker image**. High-fidelity PDF work needs real document
engines that do not exist in Render's plain Node runtime:

| Engine | Used for |
| --- | --- |
| LibreOffice | Word ⇄ PDF with the original layout, fonts, images and tables |
| Ghostscript | Genuine PDF compression (re-encodes images, subsets fonts) |
| qpdf | AES-256 password protection and permissions |
| Poppler | Layout-preserving text extraction and page rendering |
| Tesseract | On-server OCR for scanned documents |
| pdf2docx | PDF → editable Word with paragraphs and tables |

Without them the app still runs and every tool still works, but conversions fall
back to lower-fidelity JavaScript implementations. `GET /api/health` reports
exactly which engines the running server has.

---

## 1. Create the service

### Option A — Blueprint (recommended)

1. Push this repository to GitHub.
2. In Render: **New → Blueprint**, select the repo. `render.yaml` is detected
   automatically and creates the service with the right settings.

### Option B — Manual

**New → Web Service**, then set:

| Setting | Value |
| --- | --- |
| Language | `Docker` |
| Root Directory | `backend` |
| Dockerfile Path | `./Dockerfile` |
| Health Check Path | `/api/health` |

> **Instance type.** LibreOffice needs roughly 400 MB of RAM while converting.
> The 512 MB free instance will restart under load, so use **Starter or larger**
> if you want Word conversions to be reliable. Everything else runs comfortably
> on free.

The first build takes 5–10 minutes because it installs the document engines.
Later builds reuse the cached Docker layers and are much faster.

---

## 2. Environment variables

Set these under **Environment**:

| Key | Value |
| --- | --- |
| `MONGODB_URI` | Your full Atlas connection string, including the database name |
| `FRONTEND_URL` | Your deployed frontend origin, e.g. `https://mypdftools.vercel.app` |
| `JWT_SECRET` | Generated by Render |
| `SESSION_SECRET` | Generated by Render |
| `GOOGLE_CLIENT_ID` | Optional — only for Google sign-in |
| `GOOGLE_CLIENT_SECRET` | Optional |
| `GOOGLE_CALLBACK_URL` | Optional — `https://<your-api>.onrender.com/api/auth/google/callback` |
| `MAX_UPLOAD_MB` | Optional, defaults to `50` |

`MONGODB_URI` must be the real string from Atlas (**Connect → Drivers**), with
the database name inserted before the `?`:

```
mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/mypdftools?retryWrites=true&w=majority
```

If the password contains `@ : / ? # [ ] %`, percent-encode it.

---

## 3. Allow Render to reach MongoDB

In Atlas → **Network Access** → **Add IP Address** → **Allow access from
anywhere** (`0.0.0.0/0`). Render's outbound addresses are not fixed, so an
allow-list of specific IPs will not work on the free and starter plans.

---

## 4. Point the frontend at the API

In Vercel (or wherever the frontend is hosted) set:

```
VITE_API_URL=https://<your-api>.onrender.com/api
```

Then redeploy the frontend — Vite inlines environment variables at build time,
so changing this value has no effect until a rebuild.

Set `FRONTEND_URL` on Render to the frontend's origin as well, or CORS will
reject the browser's requests.

---

## 5. Verify

```bash
curl https://<your-api>.onrender.com/api/health
```

A healthy response looks like:

```json
{
  "status": "ok",
  "database": "connected",
  "capabilities": {
    "libreoffice": true,
    "ghostscript": true,
    "qpdf": true,
    "poppler": true,
    "tesseract": true,
    "pdf2docx": true
  }
}
```

Any `false` value means that engine failed to install and the related tool will
use its fallback path.

## Troubleshooting

**`querySrv ENOTFOUND` in the logs**
`MONGODB_URI` is still a placeholder. Paste the real connection string from Atlas.

**`bad auth: authentication failed`**
Wrong username or password, or an unencoded special character in the password.

**Connection times out**
Atlas Network Access is not allowing `0.0.0.0/0`.

**Word → PDF returns "approximate" fidelity**
LibreOffice is missing — check `/api/health`. On a fresh deploy this usually
means the Docker build fell back to a cached layer; trigger a manual deploy with
**Clear build cache**.

**Service restarts during a conversion**
The instance ran out of memory. Move to a larger instance type.

**First request after idling is slow**
Free and starter instances sleep when idle and take ~30 seconds to wake.
